My suggestion, and what I need from you

  • A + R1 + R3, with D's Named section as a later addition. A is the screen you described, R1 is the fastest rename, R3 gives history its own actions. B and C are good ideas but solve a second problem.
  • What does a rename change? I'd label the run only and leave the saved request's name alone, so renaming "VAT bug repro" never hurts the collection. R2's second option exists in case you'd rather rename the request.
  • How much to keep. Today Hopper keeps the newest 20 responses per saved request and nothing for unsaved sends. "All requests" needs a rule, for example 500 entries or 30 days, and labeled entries never expire.
  • Agent sends. Show requests the MCP agent made, with the AGENT badge as in A, or hide them behind a filter?
